로컬 소프트웨어

1회 설정
되돌릴 수 없는 함정

언리얼 프로젝트는 한번 올린 버전에서 내려올 수 없다. 5.8로 연 프로젝트는 5.7에서 열리지 않는다. 다른 PC·팀과 버전을 먼저 맞춘 뒤 프로젝트를 생성한다. 어긋나면 처음부터 다시 만들어야 한다.

B4

3D 생성 모델 — 이미지/텍스트 → GLB

1회 설정

"이미지→3D" 경로 에셋을 실제로 만드는 엔진. Blender MCP 안에 통합돼 있지만 각각 키와 모드를 따로 켜야 한다. 여기가 준비에서 가장 많이 빠지는 구간이다.

모델모드이미지 입력 형식키비고
Hyper3D RodinMAIN_SITE로컬 절대경로hyper3d.aifree_trial 키는 일일 생성 한도

Hyper3D를 FAL_AI로 쓰면 생성한 이미지를 URL로 올려야 하고, MAIN_SITE면 파일로 저장하면 된다.

준비 단계에서 모드를 정하지 않으면 이미지를 전부 만든 뒤 3D 변환에서 막힌다.

실제 변환 절차 — 비동기 4단

1생성 요청generate_hyper3d_model_via_images / _via_text / generate_hunyuan3d_model
2상태 폴링 — 완료까지 대기poll_rodin_job_status / poll_hunyuan_job_status. 한 번에 끝나지 않는다.
3GLB 임포트import_generated_asset / import_generated_asset_hunyuan
4크기 보정 — 빼먹으면 안 되는 단계world_bounding_box를 확인해 위치·스케일·회전을 맞춘다. 생성된 GLB는 임의 스케일로 들어온다. 브리프의 실측 크기 판정은 이 보정 뒤에 한다.

생성 모델의 한계 — 시도하지 말 것

  • 장면 전체를 한 번에 생성 — 단일 오브젝트 생성기다
  • 지면·지형 생성 — 엔진에서 만들거나 기성 에셋을 쓴다
  • 부품을 따로 생성해 나중에 조립
  • 같은 에셋을 개수만큼 재생성 — 1건 생성 후 파이썬으로 복제하고 스케일·회전 지터로 변형

브리프에 "5~7채, 크기 변형 2~3종"이라 적혀 있어도 생성은 2~3건이면 된다.

B6

머티리얼 · 텍스처 — 표면은 형태와 별개 작업

경로별로 다름

준비물이 아니라 플로우다. 에셋을 어떤 경로로 만들었는지에 따라 해야 할 일이 완전히 달라진다.

에셋 경로머티리얼 상태해야 할 일
Hyper3D / Hunyuan3D 생성포함되어 나옴 — GLB에 PBR 내장없음 · 확인만
Sketchfab / PolyHaven 모델포함되어 나옴없음 · 확인만
절차적 모델링없음 ← 실제 작업 구간UV → 텍스처 확보 → 적용

절차적 메시에 표면 입히기 — 3단

1UV 언랩 — 반드시 먼저없으면 텍스처가 늘어나거나 뭉개진다. execute_blender_code로 Smart UV Project 등을 돌린다.
2텍스처 확보download_polyhaven_asset(asset_type="textures") — 맵들이 담긴 머티리얼이 생성된다.
3적용set_texture(object_name, texture_id) — Principled BSDF에 color · roughness · metallic · normal · displacement가 연결된다.
UV 함정 · 소스에서 확인함

set_texture가 만드는 노드 그래프는 UV 좌표 출력에 연결되지만, set_texture 자체는 UV를 만들지도, 있는지 확인하지도 않는다.

절차적으로 만든 메시는 UV가 없거나 엉망인 경우가 많다. 텍스처를 붙였는데 이상하면 머티리얼 문제가 아니라 UV 문제다.

순서 함정

환경광(PolyHaven HDRI)을 먼저 넣고 나서 머티리얼을 판정한다. 조명 없는 상태에서 표면 합불을 판정하면 나중에 전부 다시 봐야 한다.

PolyHaven에 맞는 텍스처가 없거나 단색·기본 머티리얼만 필요하면 스크립팅으로 직접 만든다. 초가 지붕처럼 특정한 표면은 텍스처 라이브러리에 없을 수 있다.

절차적 모델링은 최후 수단이다. 라이브러리에 없거나 · 생성이 실패했거나 · 단순 프리미티브거나 · 규칙 기반 반복 구조(모듈 울타리 등)라 스크립팅이 오히려 정확할 때만 쓴다.

첫 회전에서 확인

후삼국 프로젝트는 하네스 설계까지만 하고 실제 에셋 제작에 들어가지 않았다. 아래는 확인하지 않은 가정이므로 사실처럼 취급하지 않는다.

  • Blender → 언리얼 머티리얼 이관 — 노드 그래프가 어디까지 옮겨지는지 확인 안 됨. 임포트 후 재작업이 필요할 수 있다
  • Quest 머티리얼·텍스처 예산 — 모바일 GPU 제약(텍스처 해상도, 드로콜, 셰이더 복잡도) 미측정
  • Hyper3D vs Hunyuan3D — "비교 후 결정"으로 남겨두고 실행하지 않았다
  • 자연 배치 수치 — 지터 ±10%, 경사 20°, 재시도 상한 3회는 근거 없는 초기값
  • 절차적 모델링 품질 — 초가집·목책이 실제로 쓸 만하게 나오는지 확인 안 됨

준비 없이 시작하면 생기는 일

  • Blender 미실행 → 모든 모델링 호출이 조용히 실패, 원인 찾는 데 시간 낭비
  • 언리얼 에디터 미실행 → 에셋은 다 만들었는데 임포트에서 전부 멈춤
  • 3D 생성 모드 미확정 → 이미지를 다 만들고 변환 단계에서 막힘
  • 크기 보정 생략 → 임의 스케일 메시가 배치돼 실측 판정을 통과할 수 없음
  • UV 없이 텍스처 적용 → 표면이 깨져 보이고 원인을 머티리얼에서 찾게 됨
  • 조명 없이 머티리얼 판정 → HDRI 넣은 뒤 전부 다시 판정
  • 언리얼 버전 안 맞춤 → 프로젝트를 처음부터 다시 (되돌릴 수 없음)
