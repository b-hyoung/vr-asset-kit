# Claude 계약서 (AGENT_CONTRACT)

이 웹 대시보드로 VR 제작을 진행할 때, Claude(및 모든 실행 AI)는 아래 규칙을 **반드시** 따른다.
이 규칙은 산문 권고가 아니라 서버가 소유한 `projects/<id>/state.json` + 게이트로 **강제**된다.

## 1. 값은 오직 state.json 에서만 읽는다
- 현재 프로젝트의 주제·배경·앵커·에셋 리스트는 **`state.json` 의 `inputs`** 에서만 가져온다.
- `examples/` 의 예시 파일, 이전 세션 기억, 문서(`RUN.md` 등) 본문의 "후삼국 실제:" 예시를
  **현재 프로젝트 값으로 취급하지 않는다.** (버그 1 방지)
- `inputs` 필드가 비어 있으면(예: `topic` 이 null) **스스로 채우지 말고**,
  "웹 대시보드 STEP에서 입력해 주세요"라고 사용자에게 안내한다.

## 2. 단계를 스스로 올리지 않는다
- 각 단계 작업을 시작하기 전, `state.steps.<이전단계>.gate_passed` 가 `true` 인지 확인한다.
- `false` 이면 **멈추고** "웹에서 이 단계를 확정(게이트 통과) 해 주세요"라고 안내한다.
- `current_step` / `gate_passed` 를 직접 수정하지 않는다. 게이트 통과는 **사용자의 웹 클릭**으로만 일어난다. (버그 2 방지)

## 3. 자기 채점 금지
- 산출물(배치·품질 등)을 스스로 합격 처리하지 않는다.
- 판정은 사용자 또는 지정된 심판 엔진(`state.engine_choices` 의 `place.judge`)이 내린다.

## 4. 엔진은 지정된 것을 쓴다
- 각 단계에서 사용할 생성 엔진/모델은 `state.engine_choices` 를 따른다
  (예: `make.image`, `make.mesh_3d`, `place.judge`). 임의로 바꾸지 않는다.

## 5. 기본 자산 보호 (전역 하드룰)
- 엔진/툴의 기본 템플릿·레벨·기본 액터(SkyLight 등)를 수정·삭제하지 않는다.
- 항상 새 사본에서 작업. 파괴적 작업 전 사용자 확인.
