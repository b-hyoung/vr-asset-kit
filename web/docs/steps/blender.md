# 4.2 블렌더 터칭 (image→3D 결과 정리)

Hunyuan 결과를 **언리얼에 넣기 전에** 블렌더에서 한 번 정리한다.
실행은 `scripts/touch_props_blender.py` — **`blender --background -P` (GUI·MCP 불필요)**.

> 왜 CLI 인가: 무인 루프에서 GUI+포트(9876) 의존은 약점이다. MCP 는 사람이 붙어 보면서
> 만질 때 쓰고, 배치 자동 처리는 CLI 가 결정적이다.

---

## ⛔ 하드룰 — UV·텍스처를 건드리지 않는다

**Smart UV Project 를 그냥 돌리면 원본 텍스처 UV 를 덮어써서 색이 통째로 날아간다.**
Hunyuan paint 출력은 텍스처와 짝이 맞는 UV 를 갖고 나온다(실측: 20,000 face / uv (10421,2) / 2048px).
재UV 가 필요하면 **반드시 리베이크까지 세트로** 해야 한다. 블록아웃 목적에는 그만한 값이 없다.

→ 터칭 스크립트는 UV 레이어와 머티리얼을 **읽기만** 한다.

> ⚠ 검사에 **정확 해시를 쓰면 안 된다.** 플로터 제거·데시메이트는 정점을 지우므로 UV 배열이
> **정당하게** 바뀐다. 실측 08-31에 해시로 검사했다가 멀쩡한 작업 3건을 전부 막았다.
> → 레이어 이름 + UV 바운딩박스 + 텍스처 노드 수로 본다. 재투영은 이 셋을 크게 흔든다.

---

## 왜 필요한가 — 안 하면 나오는 증상 (실측 08-31)

| 증상 | 원인 |
|---|---|
| 배치하면 물체가 뜨거나 바닥에 묻힘 | 원점이 바운딩박스 중심. 메시마다 바닥 높이가 다름 |
| 망치와 물레방아가 같은 크기 | Hunyuan 은 전부 **약 198cm 정육면체로 정규화**해서 낸다. 크기 관계가 통째로 소실 |
| 물체 주변에 조각이 떠다님 | Hunyuan 이 배경 잔재를 물체로 인식 (인물에서 특히 잦음) |
| VR 에서 바닥·벽을 통과 | glTF 임포트는 **단순 충돌을 만들지 않는다.** 캐릭터 캡슐은 단순 충돌에만 부딪힌다 |
| 같은 에셋 반복이 눈에 띔 | 복제본이 회전·크기까지 완전히 동일 |

> 실측 08-31, 12개 처리 결과: **떠다니는 파편 1,715개 제거**(쇳물용기 427, 제련기구 270,
> 물레방아 252, 대장장이 221 …), 20,000 → 5,000 face, 전부 목표 높이 ±1% 안.

---

## 터칭 항목 (순서 고정)

1. **플로터 제거** — 연결요소로 분리해 가장 큰 것만 남기고, 부피 임계 이하를 버린다
2. **원점 → 밑바닥 중앙**, z=0 정렬, 업축 통일
   → 이걸 하면 언리얼 배치 코드에서 바닥 보정 로직이 사라진다
3. **실측 스케일 적용** — `props.json` 의 `real_h_cm` 값으로 메시 자체를 실제 크기로 만든다
   (목표 높이를 배치 코드에 박아두면 재사용이 안 된다)
4. **데시메이트** — 블록아웃 기본 **5,000 face**. 원본 20,000 은 과하다
5. **충돌** — glb 에 동봉하지 않는다 (아래 ⛔ 항목). 언리얼 임포트에서 붙인다
6. **UV·텍스처 무터치** (위 하드룰)

---

## ⛔ 충돌 — glb 에 헐을 동봉하지 않는다 (실측 08-31)

`UCX_` 접두사 규칙은 언리얼 **FBX** 임포터의 규칙이고, **glTF/Interchange 가 인식하는지는 미확인**이다.
실제로 넣어보니 convex hull 이 본체와 같은 크기라 **뷰어에서 본체를 통째로 덮었다.**
언리얼이 UCX_ 를 못 알아보면 저게 그대로 '보이는 회색 덩어리'가 된다.

→ **기본값: 동봉하지 않는다** (`touch_embed_collision: false`).
   스크립트는 대신 **본체 메시가 딱 하나만 나가는지** 검사한다.

충돌은 **언리얼 임포트 단계에서** 붙인다:
```python
sm.get_editor_property("body_setup").set_editor_property(
    "collision_trace_flag", unreal.CollisionTraceFlag.CTF_USE_COMPLEX_AS_SIMPLE)
```
코드로 설정하고 코드로 검증할 수 있어 확실하다. 5,000 face 메시라 비용도 낮다.

> 나중에 convex 충돌이 꼭 필요해지면 그때 **FBX 경로**로 바꾼다. 지금 필요하지 않다.

**어느 쪽이든 "충돌 넣었다"고 그냥 넘어가지 말 것.** 렌더는 멀쩡한데 못 서 있는 상태가 된다.

## ⚠ glTF 는 Y-up (검증할 때 축을 헷갈리지 말 것)

블렌더는 Z-up, **glTF 는 Y-up** 이라 export 에서 축이 회전한다.
터칭 결과를 trimesh 등으로 확인할 때 `extents[2]`(Z)를 높이로 읽으면 **엉뚱한 값이 나온다.**

> 실측 08-31: 스케일이 틀린 줄 알고 되돌릴 뻔했다. 실제로는 `extents[1]`(Y)이 높이였고 값은 정확했다.

## 반복감 줄이기 (배치 단계와 연동)

같은 에셋을 여러 개 놓을 때 **재생성하지 말고 복제 + 지터**한다 (`lessons.md` 2026-08-24 규칙).
- 회전: yaw 랜덤 (0~360)
- 스케일: ±10%
- 위치: 격자에 두지 말고 소량 오프셋

> 실측 08-31: 이 규칙이 하네스에 있는데도 안 써서, 바위 5개가 전부 같은 방향으로 놓였다.

## 스크립트가 강제하는 것

`touch_props_blender.py` 는 끝나고 아래를 **스스로 검사하고, 실패하면 종료코드로 막는다.**
산문으로만 적어두면 안 지켜진다는 게 이 하네스의 전제다.

| 검사 | 실패 조건 |
|---|---|
| UV 보존 | 레이어 이름이 바뀌거나 UV 바운딩박스가 0.08 넘게 이동하면 실패 |
| 머티리얼 보존 | 머티리얼/텍스처 개수가 줄면 실패 |
| 바닥 정렬 | 바운딩박스 min z 가 0 에서 1mm 넘게 벗어나면 실패 |
| 실측 스케일 | 높이가 `real_h_cm` 대비 ±2% 밖이면 실패 |
| 폴리 예산 | 목표 face 수를 넘으면 실패 |
| 본체 단일 | 헐 미동봉 모드에서 메시가 2개 이상이면 실패 (회색 덩어리 방지) |

---

## 실행

```
blender --background --python scripts/touch_props_blender.py -- <BASE> [only=a,b]
```
- 입력: `<BASE>/export/<name>.glb` + `<BASE>/props.json`
- 출력: `<BASE>/export_touched/<name>.glb`
- 리포트: `<BASE>/touch_result.json`

`ue_import` 단계는 **`export_touched/` 를 읽는다** (원본 `export/` 아님).
