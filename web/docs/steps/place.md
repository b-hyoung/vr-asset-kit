# 5. 자동 배치 루프

배치 → **심판(판정)** → 재배치 반복.

## 규칙
- **AI 자기 채점 금지.** 판정은 사용자 또는 OpenAI 심판.
- `scatter_houses`(2D 산포)는 **1회가 최선** (다회는 과산포).
- 사용자 수동 수정 뒤에는 **assemble 재실행 금지**(다 날아감) — 개별 액터만 손대기.

> 심판 엔진은 단계 상단에서 선택 (OpenAI / Claude / 사용자 수동).

## ⛔ 검증은 8방향으로 한다 (실측 08-31 — 가장 크게 틀린 것)

한 방향만 렌더해서 "잘 나왔다"고 보고했다가, 사용자가 실제로 보고 있던 방향이
**완전한 암흑**이었다. 밝은 쪽만 골라 찍은 것이었다.

**모니터로는 한 방향만 보지만 VR 은 어디든 돌아본다.** 배치·조명 판정은 반드시
홀 중앙에서 **8방향(45° 간격) 전부** 찍고 **평균 밝기까지 수치로** 본다.

```
python -u scripts/ue_exec.py scripts/ue/render_360.py "360 check" --grep SHOT
```
- 모든 방향 평균 밝기 **6 이상**이어야 통과 (0~255 기준, 고정 노출)
- 한 방향이라도 미달이면 채움광을 넣고 다시 잰다

> 실측: 화로 쪽에 광원이 몰려 있고 SkyLight 가 0.12 라 홀 절반이 암흑이었다.
> SkyLight 0.55 + 그림자 없는 채움광 6개로 최저 밝기 10.2 까지 올렸다.

## 스케일 기준 (출처: The Level Design Book)

| 항목 | 값 |
|---|---|
| 사람 기준 | 언리얼 캐릭터 폭 60uu / 키 ~175cm |
| 벽 높이 | 기준 인물의 **150~200%** |
| 출입구·복도 폭 | 기준 인물의 **최소 2배** |
| 그리드 | 언리얼 50/100 (모듈 킷이 있으면 킷 폭에 맞춤) |

**가장 흔한 실패는 스케일이다.** 대책은 하나뿐이다 — **기준 인물을 씬에 여러 개 세워두고 짓는다.**
에디터에서 날아다니며 보지 말고, **중력·충돌 켠 채 눈높이로 걸어서** 확인한다.

> 우리 씬은 대장장이(175cm)가 기준 인물 역할을 한다. 배치 후 눈높이 165cm 렌더가 필수인 이유다.

## 프롭 배치 원칙 (출처: 80.lv / Level Design Book / Game Developer)

1. **뭉쳐 놓는다 (clustering)** — 고르게 흩뿌리지 말 것. 관련된 것끼리 작은 무리로 묶는 편이
   보기에도 낫고 플레이어가 공간을 읽기도 쉽다. 게슈탈트의 근접성 원리.
2. **초점(focal point)을 하나 만든다** — 구역마다 눈이 가는 것 하나(히어로 프롭·건축 랜드마크·광원).
   나머지 에셋은 **의도적으로 초점에 종속**시킨다. 우리 씬에서는 화로가 그 역할.
3. **대비로 흥미를 만든다** — 전부 거칠거나 전부 매끈하면 죽는다. 거친 바닥 위의 젖은 수면,
   그을린 쇠 옆의 발광하는 쇳물 같은 조합.
4. **여백을 남긴다** — 빈 바닥은 실패가 아니다. 초점이 살아나려면 주변이 비어야 한다.

## ⛔ 같은 에셋을 여러 개 놓을 때

**재생성하지 않는다. 복제 + 지터.** (`lessons.md` 2026-08-24)

| 축 | 값 |
|---|---|
| 회전 | yaw 0~360 랜덤 |
| 스케일 | ±10~30% |
| 위치 | 격자 좌표에 그대로 두지 말고 ±50~70cm 오프셋 |

> 실측 08-31: 규칙이 문서에 있는데도 안 써서 바위 5개가 전부 같은 방향으로 섰다.

### ★ 급(size tier)을 나눈다 — 지터만으론 부족하다

`props.json` 의 `real_h_cm` 은 **에셋당 하나**다. 바위 하나로 큰 바위와 자갈을 둘 다 만들려면
배치에서 **`size` 배율**을 따로 줘야 한다.

> 실측 08-31: 블렌더 터칭으로 실측 크기를 적용한 뒤, 자갈 자리까지 전부 160cm 바위가 되어
> 큐브 15개가 홀 한복판에서 시야를 막았다. 지터 ±35% 로는 자갈이 안 된다.
> → 큰 바위 0.85× 3개(벽 쪽) / 자갈 0.30× 15개 로 급을 나눠 해결.

## 구도 다듬기 체크리스트 (실측 08-31)

- **다리 과대/상자처럼 보임** → 스케일 하향 + 난간·상판 디테일 살리기(밋밋한 큐브 방지).
- **강물이 시점 따라 안 보임** → 수면을 넓히거나 카메라 높이/각 조정.
- **은하수·별이 약함** → 방출/개수 상향(단 별 과다는 크래시 유발 → 적정선).
- **성이 어두움** → 성 쪽 필/스포트라이트 보강(기본 SkyLight는 건드리지 않음).
- **큰 물체가 시야를 막음** → 큰 것은 **벽 쪽으로**, 통로 중앙은 무릎 높이 이하만.

> 이 단계는 **제자리 편집만**(ue_import의 크래시 회피 하드룰 준수). assemble/레벨전환 재실행 금지.

## ⚠ 검수 렌더의 카메라 (실측 08-31 — 멀쩡한 걸 망가졌다고 오판했다)

메시 미리보기를 **pitch 70°(탑다운)** 로 찍었다가, 서 있는 인물 메시를 "부서졌다"고 잘못 보고했다.
- 프롭·인물 확인은 **pitch 0~20°**
- 배치 확인은 **눈높이 165cm**
- 부감은 전체 레이아웃 볼 때만

## VR 로 갈 거면 (실측 08-31)

- **개활 홀은 RDW 에 불리하다.** 직선 시야가 길면 사람이 직선으로 걷고, 그러면 곡률 게인을
  못 먹인다. 벽·바위로 **시야를 끊어 굽은 통로**를 만들면 같은 면적에서 동선을 늘리면서
  리셋을 줄일 수 있다.
- **겹치는 동적 그림자 라이트는 4개까지.** 넘으면 언리얼이 경고하고, VR 은 양안이라 비용이 2배다.
  극적인 1~2개만 그림자를 켜고 나머지는 빛만 남긴다 — 화면은 거의 안 변한다(실측).
- 면적을 실제 공간과 대조할 것. 27×22.5m 홀은 **183.8평** 이다.

## 배경 참고 이미지가 있으면 ★
`state.ref_images[0].path` 가 **배치의 기준**이다. 배경 자체를 씬에 넣지는 않는다.
