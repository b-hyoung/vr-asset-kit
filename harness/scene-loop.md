# 실행 하네스: 장면 제작 루프 (에셋 다종 생성 → 자연 배치 → 장면 완성)

목표: 장면 브리프 1개를 입력으로, 필요한 에셋 여러 종을 루프로 생성하고
자연스럽게 배치해 장면을 완성한다.
범위 제외: 빌드, VR 실기 검수 (별도 루프)

규칙: 이 루프를 수정하거나 새 루프를 만들 때는 `meta.md`의 8개 질문을 먼저 통과해야 한다.

## 전체 흐름

```
[장면 브리프] → [에셋 리스트 확정]
                     ↓ 에셋마다 반복 ⟲
              생성(Blender / 이미지→3D) → 판정(재시도 최대 3) → 임포트(엔진)
                     ↓ 전부 준비되면
              [장면 배치] → [장면 검증: 다각도 캡처 + 리포트]
```

## 에셋 생성 경로

| 경로 | 언제 | 도구 |
|---|---|---|
| 절차적 모델링 | 규칙으로 기술 가능한 형태(건물, 구조물, 모듈 반복) | Blender MCP |
| 이미지→3D | 유기적·불규칙 형태(자연물, 소품, 곡면) | 이미지 생성 → Hyper3D / Hunyuan3D |
| 기존 재활용 | 이미 쓸 만한 에셋이 있음 | 루프 제작 대상 아님, 배치만 |

이미지 생성 전에는 반드시 `questions.md`의 슬롯 8개를 채운다. 하나라도 비면 생성 금지.

### 이미지→3D 세부 절차 (비동기 3단 — 한 번에 끝나지 않는다)

```
1. 생성 요청   generate_hyper3d_model_via_images / _via_text
               generate_hunyuan3d_model
2. 상태 폴링   poll_rodin_job_status / poll_hunyuan_job_status   ← 완료까지 대기
3. 임포트      import_generated_asset / import_generated_asset_hunyuan  (GLB)
4. 크기 보정   ★ world_bounding_box를 확인해 위치·스케일·회전을 맞춘다
```

**4번을 빼먹으면 안 된다.** 생성된 GLB는 임의 스케일로 들어온다.
브리프의 실측 크기 판정은 이 보정 후에 한다.

### 3D 생성 모델의 한계 (반드시 지킬 것)

Hyper3D·Hunyuan3D는 **단일 오브젝트 생성기**다. 다음을 시도하지 않는다:

- ❌ 장면 전체를 한 번에 생성
- ❌ 지면(ground)·지형을 생성 — 지형은 엔진에서 만들거나 기성 에셋을 쓴다
- ❌ 부품을 따로 생성해 나중에 조립

에셋 1종 = 생성 1건. 이 제약이 하네스의 "에셋 단위 루프" 구조와 정확히 맞물린다.

### 복제 재사용 (생성 비용 절약)

같은 에셋을 여러 개 배치할 때 **재생성하지 않는다.** 한 번 생성해 임포트한 오브젝트를
파이썬으로 복제하고, 배치 규칙의 스케일·회전 지터로 변형을 준다.
브리프에 "5~7채, 크기 변형 2~3종"처럼 적혀 있어도 **생성은 2~3건**이면 된다.

### 머티리얼·텍스처 (표면) — 경로마다 다르다

형태와 표면은 별개 작업이다. **에셋 제작 경로에 따라 해야 할 일이 완전히 다르다.**

| 에셋 경로 | 머티리얼 상태 | 해야 할 일 |
|---|---|---|
| Hyper3D / Hunyuan3D 생성 | **포함되어 나옴** (GLB에 PBR 내장) | 없음 — 확인만 |
| Sketchfab / PolyHaven 모델 | **포함되어 나옴** | 없음 — 확인만 |
| **절차적 모델링** | **없음** ← 여기가 실제 작업 구간 | 아래 3단 |

#### 절차적 메시에 표면 입히기

```
1. UV 언랩      ★ 먼저. 없으면 텍스처가 깨져 붙는다 (아래 함정)
2. 텍스처 확보   download_polyhaven_asset(asset_type="textures")
                → 맵들이 담긴 머티리얼이 생성된다
3. 적용         set_texture(object_name, texture_id)
                → Principled BSDF에 color/roughness/metallic/normal/displacement 연결
```

⚠️ **UV 함정 (검증됨)**: `set_texture`가 만드는 노드 그래프는 **UV 좌표 출력에 연결**되지만,
`set_texture`는 **UV를 만들지도, 있는지 확인하지도 않는다.**
절차적으로 생성한 메시는 UV가 없거나 엉망인 경우가 많다 →
텍스처를 붙였는데 늘어나거나 뭉개지면 머티리얼 문제가 아니라 **UV 문제**다.
`execute_blender_code`로 Smart UV Project 등을 먼저 돌린다.

PolyHaven에 맞는 텍스처가 없거나 **단색·기본 머티리얼만 필요하면** 스크립팅으로 직접 만든다.
(초가 지붕처럼 특정한 표면은 텍스처 라이브러리에 없을 수 있다)

#### 환경광은 머티리얼이 아니지만 표면 룩을 지배한다
PolyHaven **HDRI**를 먼저 넣고 나서 머티리얼을 판정한다.
조명이 없는 상태에서 머티리얼 합불을 판정하면 나중에 전부 다시 봐야 한다.

### 에셋 소스 우선순위 (제작 경로 결정 기준)

`meta.md` §3에서 경로를 정할 때 이 순서로 판단한다 — **만들기 전에 가져올 수 있는지 본다.**

| 대상 | 1순위 | 2순위 |
|---|---|---|
| 특정 실존 오브젝트 | Sketchfab | PolyHaven |
| 일반적 오브젝트·가구 | PolyHaven | Sketchfab |
| 라이브러리에 없는 고유 에셋 | Hyper3D / Hunyuan3D 생성 | — |
| 환경광 | PolyHaven HDRI | — |
| 머티리얼·텍스처 | PolyHaven 텍스처 | 스크립팅 |

**절차적 모델링(스크립팅)은 최후 수단이다.** 다음일 때만 쓴다:
- 라이브러리 어디에도 적당한 게 없다
- 생성 모델이 원하는 결과를 못 냈다
- 단순 프리미티브나 기본 머티리얼만 필요하다
- 규칙 기반 반복 구조(모듈 울타리 등)라 스크립팅이 오히려 정확하다

### 기성 에셋 우선 판단

만들기 전에 가져올 수 있는지 본다 — PolyHaven(모델·텍스처·**HDRI 환경광**), Sketchfab(현실적 모델).
환경광은 거의 항상 가져오는 쪽이 맞다. 생성 대상 목록에 HDRI를 넣지 않는다.

## 판정 기준 (에셋별)

- 폴리곤 예산·실측 크기 준수 (브리프 수치)
- 형태 필수 요소 존재 (브리프 슬롯 6)
- **표면**: 머티리얼 적용됨, UV 왜곡 없음, 스타일 앵커와 톤 일치
- 배제 요소 미포함 (브리프 슬롯 7)
- 3연속 불합격 시 해당 에셋 건너뛰고 **보고** (루프 전체는 계속)
- 판정은 사용자가 한다 — AI가 스스로 합격 처리하지 않는다

## 자연 배치 규칙 (범용 · 개별 층)

- 지면 스냅(라인트레이스), 공중부양·파묻힘 금지
- 랜덤 회전 + 스케일 지터 ±10%, 균등 간격 금지
- 상호 겹침 금지, 에셋별 최소 이격 지정
- 경사 20° 초과 지점 배치 금지
- 같은 에셋 반복 시 변형(크기·회전)을 섞어 복붙 느낌 제거

## 구성 규칙 (장면 전용 층)

동선·상대 배치·군집 규칙은 **장면마다 다르므로 여기 두지 않는다.**
각 프로젝트의 장면 브리프(`docs/scenes/*.md`)에 정의한다. (`meta.md` §4)

## 장면 검증

- 브리프의 완성 판정 항목을 그대로 체크
- 정해진 각도 3개 이상에서 캡처
- 마지막 질문은 항상 정성 판정: **"의도한 장소로 보이는가?"** — 사용자가 답한다
- 결과는 `docs/checks/`에 기록

## 회고 (루프 1회전 종료 시 필수)

이번 회전에서 실제로 실패한 것만 규칙으로 승격한다.
- 프로젝트 한정 규칙 → 해당 프로젝트 브리프에
- 어느 장면에나 해당 → `vr-harness/`의 이 파일 또는 `meta.md`에, 출처를 `lessons.md`에 기록
